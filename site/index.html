Se déconnecter
Les scripts s'exécutent sur le poste où cette page est ouverte. Rapports et dossiers de migration restent en local : rien n'est envoyé au site.

Le catalogue des scripts (manifest.json) est introuvable : le build n'a pas été exécuté lors du déploiement (il génère manifest.json, scripts/ et lanceur/). En local, lancer d'abord node outils/build.mjs.

Poste de travail

Migration d'un utilisateur vers un nouveau poste. Les deux scripts tournent dans la session de l'utilisateur, sans élévation : ils lisent et écrivent son profil.

Diagnostics

Diagnostics du poste sur lequel la console est ouverte, en lecture seule. Chaque diagnostic ouvre un rapport HTML (synthèse, points à traiter, commandes de correction) enregistré dans Bureau\Rapports-Audit. Les diagnostics marqués « Session utilisateur » doivent tourner dans la session de la personne concernée.

Administration

Audits en lecture seule. Chaque script demande le serveur et les identifiants, puis ouvre un rapport HTML enregistré dans Bureau\Rapports-Audit du compte qui l'exécute.

Lanceur sur ce poste

Un navigateur ne peut pas exécuter de programme. Le lanceur fait le lien : une petite installation par utilisateur, sans droits administrateur, qui associe les boutons « Lancer » à PowerShell. Il est valable 8 heures, puis se retire seul du poste.

Installer : ouvrir PowerShell (normal, pas administrateur) sur le poste, coller la commande, Entrée. Relancer la même commande prolonge le lanceur de 8 heures.


        

      

      
Ce qui se passe à chaque clic sur « Lancer »

      

        
    
          
  1. Le navigateur demande d'ouvrir « Console IT » : accepter (cocher « toujours autoriser » si proposé).
    2. 
          
  2. Le lanceur lit le catalogue de ce site, télécharge le script et vérifie son empreinte SHA-256.
    3. 
          
  3. Une fenêtre sur le poste affiche l'action, le mode d'exécution et l'empreinte : confirmer.
    4. 
          
  4. Action d'administration : Windows demande l'élévation (UAC). Action poste : PowerShell s'ouvre dans la session de l'utilisateur.
    5. 
        

        
Le lien ne transporte qu'un identifiant d'action : aucun paramètre ni aucune commande ne peut être passé par une page web. Seuls les scripts du catalogue de ce site peuvent être lancés, et toujours après confirmation sur le poste.
